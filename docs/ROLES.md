# Роли и права MedFlow

Права проверяются **на сервере** в каждом API-маршруте (`requirePerm`). Меню в интерфейсе строится из тех же прав: `/api/auth/me` отдаёт итоговые `perms` и `tabs`. Скрытая вкладка ничего не защищает сама по себе: прямой вызов API без права возвращает 403. В демо-режиме матрица та же, демо не расширяет права. Это проверяется HTTP-тестами `tests/http/v3.test.ts` на обоих режимах.

Принцип: минимально необходимые права. Регистратор не видит медицинскую часть ЭМК. Маркетолог не видит ПДн. Руководитель работает с отчётами без ФИО пациентов.

## Пояснения к решениям

- **Регистратор:**
  - пациента ищет поиском (ФИО, телефон, № карты);
  - без запроса видит только записанных на ближайшие дни;
  - вся картотека открывается явным действием, которое пишется в аудит;
  - не получает: медполя визитов, заметки врача, диагнозы в документах, интеграции, склад, `patients.manage` (объединение и удаление карт, анонимизация).
- **Касса:**
  - возврат (`cash.refund`) и отмену неотправленного чека делает только администратор;
  - скидку выше `DISCOUNT_MAX_PERCENT` кассир проводит только по одноразовому коду, который администратор выдаёт с правом `cash.discount_override`; срок кода `DISCOUNT_APPROVAL_TTL_MIN`.
- **Врач:**
  - при `DOCTOR_SCOPE=own` видит только своих пациентов;
  - приём (`visits.write`) ведёт только врач.
- **Администратор:** ЭМК только на чтение, приём не ведёт.
- **Служебные вызовы** (планировщик по `x-service-key`):
  - это отдельный тип «служебный вызов», а не пользователь и не роль;
  - разрешён только запуск воркеров (`PROCESS`);
  - в аудит записываются с `actor: service`.

## Настройка без правки кода: `RBAC_OVERRIDES`

Пример: регистратору убрать кассу (в клинике отдельный кассир), руководителю дать просмотр кассы.

```env
RBAC_OVERRIDES={"REGISTRAR":{"remove":["cash.read","cash.pay","cash.fiscalize"]},"HEAD":{"add":["cash.read"]}}
```

- JSON проверяется при старте. Неизвестная роль, неизвестное право или неверный формат: приложение не стартует и пишет понятную ошибку.
- Ограничители закона конфигом не снимаются:
  - права врачебной тайны (`medical.read`, `ai.*`, `visits.write`, `labs.create`) только у DOCTOR и ADMIN (323-ФЗ, ст. 13);
  - маркетологу нельзя выдать права на ПДн и медданные (152-ФЗ, минимизация).
- Изменение применяется после перезапуска app (`docker compose up -d app`).

## Вход и 2FA

- TOTP обязателен для ролей из `TWO_FA_ROLES`. По умолчанию это все роли с доступом к ПДн: ADMIN, REGISTRAR, DOCTOR, HEAD.
- Для SSO `OIDC_MFA_ROLES` по умолчанию совпадает с `TWO_FA_ROLES`.
- Блокировки входа:
  - логин+IP: 5 ошибок за 15 минут;
  - IP: 30 ошибок;
  - логин глобально: 100 ошибок.
- Снять блокировку: `npm run cli -- unlock --login <логин> [--ip <адрес>]`.

## Удаление сотрудников

Журнал аудита неизменяем (триггер БД). Поэтому сотрудника с записями в аудите удалить нельзя: удаление обнулило бы `userId` в журнале, а триггер такое изменение запрещает.

Сотрудника **деактивируют**:
- `active = false`;
- все его сессии завершаются;
- вход невозможен.
